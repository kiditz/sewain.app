# Security review backend dan frontend

**Tindak lanjut:** patch dan hasil regresi tersedia pada [laporan remediasi](/Users/rifkyaditya/Playground/sewain/docs/security/remediation-2026-11-06.md). Temuan di bawah mempertahankan kondisi saat review awal.

Tanggal: 6 November 2026. Lingkup: autentikasi, otorisasi objek/tenant, katalog publik, cart/checkout, upload media, dan renderer storefront pada working tree saat review.

**Hasil: 7 temuan — 5 prioritas tinggi (P1), 2 prioritas menengah (P2).** Ini review source dan satu reproduksi renderer lokal, bukan penetration test atau pernyataan bahwa production aman/telah dieksploitasi. Tidak ada endpoint migrasi, transaksi, atau payload berbahaya yang dijalankan. Tidak ada kode aplikasi yang diubah untuk review ini.

## SEC-01 — Update merchant lintas pemilik

**Bukti:** [MerchantCommandServiceImpl.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/merchants/MerchantCommandServiceImpl.java:46), [controller](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/merchants/MerchantCommandController.java:27).

`PUT /api/merchants/{id}` hanya mengambil user ID dari token, lalu service memakai `merchantRepository.findById(merchantId)` tanpa predicate pemilik atau pemeriksaan membership/role pada merchant target. Setelah mapping perubahan, service memanggil `merchant.setUserId(userId)`.

Akun login yang mengetahui ID merchant lain dapat mengubah nama, slug, publikasi, domain, dan informasi bisnis merchant target, sekaligus memindahkan `user_id` ke dirinya. Ini dapat membuat merchant menghilang dari hasil `findByUserId` pemilik aslinya setelah cache kedaluwarsa. Jangan menyamakan ini dengan bukti akses penuh ke database tenant: tabel membership `merchant_users` tidak ikut dipindahkan oleh jalur ini.

TenantFilter tidak menutup celah objek ini: membership yang diperiksa berasal dari tenant request, bukan dari `{id}` merchant target. Request memakai konteks public atau tenant milik pemanggil tetap mencapai lookup objek target. Entity Merchant sendiri dipetakan ke schema `public`.

**Perbaikan:** cari merchant berdasarkan ID dan principal yang berwenang, atau validasi role pada ID target sebelum mapping. Jangan mengubah `userId` dalam update profil biasa. Transfer pemilik harus menjadi operasi khusus dengan aturan tersendiri.

**Regresi yang perlu dibuat:** user A tidak bisa mengubah merchant B, baik tanpa header tenant maupun dengan tenant A; response 403/404 dan seluruh metadata/pemilik B tetap sama. Update milik sendiri tidak mengganti pemilik secara implisit.

## SEC-02 — Endpoint migrasi publik

**Bukti:** [SecurityConfig.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/config/SecurityConfig.java:44), [MerchantCommandController.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/merchants/MerchantCommandController.java:33), [MerchantSchemaService.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/merchants/MerchantSchemaService.java:49).

`/api/merchants/migrate` ada dalam `permitAll`. Method controller tidak memeriksa principal/role dan memanggil `migrateAllTenantSchemas()`, yang menjalankan Flyway untuk semua schema merchant.

Pihak anonim bisa memicu pekerjaan database lintas tenant, menjalankan migrasi yang sedang pending, serta mengulang pekerjaan migrasi yang membebani database. Dampaknya dapat mencakup lock dan gangguan ketersediaan. Panggilan tanpa pending migration pun masih memasuki workflow seluruh schema. Endpoint ini sengaja tidak dipanggil saat review.

**Perbaikan:** keluarkan dari API publik. Utamakan job deployment/CLI internal; jika endpoint dipertahankan, batasi ke operator platform, tambahkan audit, pencegahan eksekusi paralel, dan kontrol jaringan. Role merchant owner biasa tidak cukup untuk operasi seluruh tenant.

**Regresi:** request anonim dan akun merchant biasa ditolak sebelum service dipanggil; hanya operator platform yang dapat menjalankan job.

## SEC-03 — Customer-cart IDOR

**Bukti:** [CartController.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/orders/CartController.java:17), [CartServiceImpl.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/orders/CartServiceImpl.java:125), [SecurityConfig.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/config/SecurityConfig.java:52).

Seluruh `/api/cart/**` publik. `X-Customer-Id` langsung menjadi identitas cart. Service mencari `findByCustomerIdAndStatus` tanpa mengikat customer tersebut ke identitas login. `validateOwner` hanya memastikan tepat satu dari customer ID atau guest token terisi; itu bukan pemeriksaan kepemilikan.

Dengan customer UUID yang diketahui pada tenant target, pihak anonim dapat membaca cart dan mengubah/menghapus item cart customer itu. UUID yang sulit ditebak membatasi discovery, tetapi bukan otorisasi.

Tambahan: `getCart` tidak memanggil `validateOwner`. GET tanpa kedua header akan mencapai lookup guest token bernilai null. Pada derived query Spring Data, parameter null dapat menjadi `IS NULL`; jika ada customer-owned cart dengan guest token null, hasilnya bergantung data dan bisa membocorkan cart atau menghasilkan error non-unique. Jalur ini belum diuji terhadap database.

**Perbaikan:** derive customer ID dari sesi/token customer terverifikasi. Selama login customer belum tersedia, tolak jalur `X-Customer-Id` pada API anonim dan gunakan guest token acak sebagai capability. Wajibkan validasi owner pada GET juga. Semua operasi harus memakai owner yang ditentukan server.

**Regresi:** tanpa identitas, header customer palsu, atau identitas customer lain tidak boleh membaca/mengubah cart; pemilik sah dan guest token sah tetap dapat mengakses cartnya sendiri.

## SEC-04 — Katalog publik menggunakan data model admin

**Bukti:** [SecurityConfig.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/config/SecurityConfig.java:48), [ProductQueryServiceImpl.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/catalogs/ProductQueryServiceImpl.java:32), [ProductVariantResponse.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/catalogs/ProductVariantResponse.java:8), [InventoryUnitResponse.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/catalogs/InventoryUnitResponse.java:6).

GET produk dibuka publik, tetapi search memakai filter request tanpa memaksakan status publik. Caller dapat menghilangkan status atau meminta `status=DRAFT`. Lookup by ID dan slug juga tidak mengecek status publik.

Response yang sama dipakai untuk admin dan pengunjung. Variant mengandung `buyPrice` dan `inventoryUnits`; unit inventaris mengandung barcode, serial number, status, dan catatan kondisi. Mapper tidak meredaksi field-field tersebut. Pengunjung dapat memperoleh produk draft beserta detail operasional ketika data tersebut tersedia. Filter `status: ACTIVE` pada composable frontend hanya mengatur UI, bukan batas keamanan API.

**Perbaikan:** buat public query/DTO terpisah dari merchant query/DTO. Public query memaksakan aturan visibility di server; public DTO tidak mengirim harga beli, daftar unit fisik, serial number, atau catatan internal. Sesuaikan kebijakan UNLISTED secara eksplisit: akses detail yang disengaja tidak berarti boleh ikut search publik. Tetap izinkan admin membaca draft melalui endpoint terproteksi.

**Regresi:** caller anonim tidak dapat meminta draft lewat search, ID, maupun slug; field internal tidak ada dalam JSON publik, termasuk untuk produk ACTIVE.

## SEC-05 — Stored XSS pada HTML storefront

**Bukti:** [TextBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/TextBlock.vue:53), [HeadingBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/HeadingBlock.vue:44), [EyebrowBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/EyebrowBlock.vue:43), [BlockLabel.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/BlockLabel.vue:5), [ThemeLibraryService.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/storefront/ThemeLibraryService.java:258).

Text, Heading, dan Eyebrow memasukkan string ke `v-html` tanpa sanitizer. BlockLabel hanya memeriksa apakah string mengandung salah satu tag rich text; jika iya, seluruh string dikembalikan utuh. Jadi adanya `<p>` cukup untuk meloloskan tag/atribut aktif lain. Product description juga masuk renderer HTML. Backend memvalidasi struktur JSON theme, tetapi tidak memvalidasi HTML pada setting; product description adalah string bebas.

**Reproduksi lokal yang dilakukan:** BlockLabel dikompilasi menggunakan Vue compiler lalu dirender dengan Vue SSR di Node. Input inert berikut menghasilkan atribut `onerror` yang tetap utuh di output:

```html
<p>security-review</p><img src="x" onerror="/* review-marker */">
```

Hasil pengecekan: `renderedEventAttributeUnchanged: true`. Tidak ada JavaScript berbahaya yang dieksekusi. Reproduksi membuktikan HTML tidak dibersihkan; dampak eksekusi di browser diturunkan dari penggunaan `v-html`, bukan dari browser exploit yang dijalankan saat review.

Theme JSON yang diimpor atau konten tersimpan dapat menjadi jalur ke preview merchant dan storefront publik. UI Quill/toolbar tidak menjadi trust boundary karena request/import bisa melewati editor. Jika konten dibuka oleh merchant pada origin yang sama dengan dashboard, risikonya termasuk pencurian bearer token: [useAuth.ts](/Users/rifkyaditya/Playground/sewain/web/app/composables/useAuth.ts:8) menyimpan access token di cookie yang dapat dibaca JavaScript.

**Perbaikan:** sanitizer berbasis parser dengan allowlist elemen/atribut/protokol sesuai format rich text. Terapkan pada write/import dan render untuk melindungi data lama. Hapus event handler, elemen aktif, URL berbahaya, dan atribut style yang tidak dibutuhkan. Regex pendeteksi tag bukan sanitizer. Tambahkan CSP yang sesuai Nuxt sebagai pertahanan tambahan, bukan pengganti sanitizer.

**Regresi:** rich text sah tetap tampil, sementara event handler, markup aktif, dan link berprotokol berbahaya ditolak/dibersihkan pada editor preview dan halaman publik. Pengujian harus mencakup data dari import, API langsung, dan data lama.

## SEC-06 — Upload file aktif dengan MIME yang dipalsukan

**Bukti:** [MediaCommandServiceImpl.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/media/MediaCommandServiceImpl.java:105), [pemeriksaan MIME](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/media/MediaCommandServiceImpl.java:166), [ekstensi](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/media/MediaCommandServiceImpl.java:190), [MediaWebConfiguration.java](/Users/rifkyaditya/Playground/sewain/backend/src/main/java/app/sewain/media/MediaWebConfiguration.java:18).

Upload normal hanya mengecek non-empty dan Content-Type multipart berawalan `image/`. Nilai itu dikendalikan caller. Ekstensi dari nama asli dipertahankan dan file disediakan lewat resource handler publik. File HTML dengan nama `.html` dan MIME multipart `image/png` dapat melewati validasi; SVG aktif juga masuk kategori `image/*`. Resource resolver hanya melakukan penanganan khusus untuk signature PNG, bukan sanitasi semua upload.

Ini memungkinkan hosting konten aktif pada origin penyedia media saat file dibuka sebagai dokumen. Dampak ke sesi frontend bergantung apakah origin/host/cookie media dan aplikasi berbagi trust boundary di deployment. Memuat SVG dalam `<img>` sendiri tidak disamakan dengan eksekusi script; risiko yang dimaksud adalah navigasi langsung atau embedding dokumen aktif. Review tidak meng-upload file percobaan.

**Perbaikan:** allowlist raster yang diperlukan, verifikasi melalui decoder, batasi dimensi/dekompresi, dan tentukan ulang ekstensi serta MIME dari hasil verifikasi/re-encode. Jika SVG dibutuhkan, sanitasi dengan kebijakan khusus atau rasterisasi. Sajikan user content dari origin tanpa cookie aplikasi; gunakan response headers yang sesuai. Batasi resource handler ke prefix media.

**Regresi:** mismatch MIME/ekstensi/isi, HTML berlabel image, dan SVG aktif harus ditolak; raster valid dan penggantian hasil hapus-background tetap bekerja. Batas multipart 5 MB/file dan 20 MB/request yang sudah ada tidak menggantikan validasi format.

## SEC-07 — URL block mentah sampai ke href

**Bukti:** [ButtonBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/ButtonBlock.vue:22), [LogoBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/LogoBlock.vue:38). Pembanding yang sudah membatasi protokol: [PolicyLinkBlock.vue](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/components/blocks/PolicyLinkBlock.vue:9), [social-links.ts](/Users/rifkyaditya/Playground/sewain/web/app/features/storefront-builder/utils/social-links.ts:16).

Button dan Logo memakai URL tersimpan langsung sebagai href. Validasi struktur theme tidak memfilter protocol pada block settings. Picker link di editor membatasi input normal, tetapi tidak membatasi JSON impor/API/data lama. URL `javascript:` dapat menjadi jalur eksekusi saat pengguna menekan link, bahkan setelah temuan sanitasi rich text diperbaiki.

**Perbaikan:** resolver URL bersama pada backend dan renderer. Utamakan ref/target tersimpan untuk link internal; untuk URL eksternal izinkan hanya protokol yang didukung. Canonicalize sebelum memeriksa protokol dan tangani karakter kontrol. Data lama/impor harus melewati aturan yang sama. Jangan menyamakan URL gambar dengan URL navigasi.

**Regresi:** navigasi internal dan HTTPS sah tetap berfungsi; `javascript:`, `data:`, varian kapitalisasi/karakter kontrol, dan protocol-relative URL yang tidak diizinkan tidak boleh menjadi href aktif.

## Gap hardening dan hal yang perlu dikonfirmasi

Hal-hal berikut dipisahkan dari tujuh temuan utama karena sebagian dampaknya bergantung pada kebijakan atau infrastruktur:

- **Role merchant belum di-enforce.** OWNER/ADMIN/MEMBER ada di MerchantRole, tetapi TenantAccessService hanya mengecek membership dan API sensitif tidak memakai role guard. Tetapkan matriks hak akses sebelum menganggap MEMBER setara administrator. Periksa khusus perubahan payment settings, finance, data pelanggan, dan publish theme.
- **Fail-open tenant dan reserved slug.** Slug tidak ditemukan jatuh ke `public`; schema public melewati pemeriksaan membership. Slug validator menerima `public`. Pisahkan routing global dari operasi tenant, reject tenant tidak dikenal untuk endpoint tenant, dan reserve nama schema/domain internal. Tidak diklaim sebagai pembacaan data tenant lain yang sudah terbukti pada review ini.
- **Proteksi abuse.** Tidak ditemukan rate limiter aplikasi untuk login, registrasi, cart, dan submission publik. Honeypot form mudah dilewati. Konfirmasi apakah ingress/WAF sudah membatasi request, lalu tambahkan limit per IP/tenant/identitas dan batas resource. Klaim consent dari form publik bukan bukti kepemilikan alamat email; jangan memperlakukannya sebagai login/email terverifikasi.
- **Sesi dan token.** JWT berlaku satu hari; logout frontend hanya menghapus state/cookie lokal. Token yang sudah dicuri tidak ikut dicabut lewat jalur logout ini. Pertimbangkan access token singkat, revocation/rotation sesuai kebutuhan, dan BFF/session cookie HttpOnly+Secure bila arsitektur memungkinkan. Tidak cukup hanya menambahkan HttpOnly karena frontend sekarang membaca token untuk header Authorization.
- **Konfigurasi produksi.** Default config memiliki credential database lokal, HTTP API base URL, dan logging Spring Security TRACE. Pastikan produksi memakai secret eksternal, HTTPS, level log terkontrol, CORS sesuai origin produksi, dan security headers/CSP di frontend. Reverse proxy, TLS, dan header production tidak diverifikasi dalam review ini.
- **Dependensi.** Versi package/build diperiksa sebagai konteks, tetapi tidak ada audit advisory/CVE terkini atau scan registry pada review ini. Tidak menyatakan dependensi bebas kerentanan.

## Kontrol yang sudah baik

- Password di-hash dengan BCrypt; JWT ditandatangani RSA dan memiliki expiry.
- Tenant schema pada koneksi divalidasi dan di-quote; search produk menggunakan allowlist field dan Criteria/Specification, bukan konkatenasi SQL input.
- Context tenant dibersihkan pada finally dan search_path koneksi direset saat release.
- Harga order dihitung kembali dari katalog oleh MerchantOrderCreationService; total cart dari client tidak langsung menjadi harga order checkout. Karena itu tidak dilaporkan sebagai bypass harga order.
- Theme import memiliki batas ukuran, kedalaman, jumlah node, dan allowlist jenis block/section. Ini bermanfaat, meskipun belum membersihkan HTML/URL setting.
- Controller submission hanya membuka POST untuk publik; listing dan delete berada di balik autentikasi.
- Penggantian media memakai staged/backup file dan transaksi; path read/replace dinormalisasi dan dibatasi ke storage root.
- File runtime/JWT lokal berada dalam aturan gitignore; tidak ditemukan file private key yang tracked pada pemeriksaan path terkait.

## Urutan penanganan

1. Tutup migrasi publik dan perbaiki otorisasi update merchant serta cart.
2. Pisahkan public product query/DTO dari admin.
3. Perbaiki sanitasi rich text dan resolver URL, termasuk data lama serta theme import.
4. Perketat validasi upload dan isolasi origin media.
5. Lengkapi matriks role, tenant fail-closed, proteksi abuse, dan konfigurasi produksi.

Validasi lanjutan sebaiknya memakai tenant/customer uji terisolasi dengan assertion 401/403/404, tanpa menjalankan migrasi atau mengubah data toko nyata. Aplikasi belum diubah oleh review ini.
